RC4 Key Scheduling Algorithm

Aim and Objectives

Aim:

To understand, visualize, and implement the RC4 Key Scheduling Algorithm (KSA) and understand how it initializes the state array, followed by the generation of the keystream using the Pseudo-Random Generation Algorithm (PRGA) for encryption and decryption.

Objectives:

  • To visualize the initialization of the 256-byte state array `S`.
  • To understand the swapping mechanism involved during the KSA.
  • To visualize how the PRGA generates the keystream byte by byte.
  • To perform RC4 encryption and decryption on given strings.

Relevant Theoretical Concepts

What is RC4?

RC4 is a symmetric stream cipher and variable-length key algorithm. This algorithm encrypts one byte at a time (or larger units at a time). A key input is a pseudorandom bit generator that produces a stream 8-bit number that is unpredictable without knowledge of the input key. The output of the generator is called the key-stream, which is combined one byte at a time with the plaintext stream cipher using the XOR operation. It was designed by Ron Rivest for RSA Security in 1987.

Applications

RC4 is used in the Secure Socket Layer (SSL)/Transport Layer Security (TLS) standards defined for communication between Web browsers and Servers. It is also used in the Wired Equivalent Privacy (WEP) protocol and the newer WiFi Protected Access (WPA) protocol that are part of the IEEE 802.11 wireless LAN standard.

Step-by-Step Procedure

1. Key-Generation Algorithm (KSA)

A variable-length key from 1 to 256 bytes is used to initialize a 256-byte state vector S, with elements S[0] to S[255]. S contains a permutation of all 8-bit numbers from 0 through 255. For encryption and decryption, a byte k is generated from S by selecting one of the 255 entries in a systematic fashion, then the entries in S are permuted again.

Initialization

The entries of S are set equal to the values from 0 to 255 in ascending order, and a temporary vector T is created. If the length of the key K is 256 bytes, then K is assigned to T. Otherwise, for a key with length (k-len) bytes, the first k-len elements of T are copied from K, and then K is repeated as many times as necessary to fill T.

For i = 0 to 255 do
  S[i] = i;
  T[i] = K[i mod k-len];

Initial Permutation of S

We use T to produce the initial permutation of S. Starting with S[0] to S[255], and for each S[i], the algorithm swaps it with another byte in S according to a scheme dictated by T[i], but S will still contain values from 0 to 255:

j = 0;
for i = 0 to 255 do {
  j = (j + S[i] + T[i]) mod 256;
  Swap(S[i], S[j]);
}

2. Pseudo random generation algorithm (PRGA) / Stream Generation

Once the vector S is initialized, the input key will not be used. In this step, for each S[i], the algorithm swaps it with another byte in S according to a scheme dictated by the current configuration of S. After reaching S[255] the process continues, starting from S[0] again. 

i, j = 0;
while (true) {
  i = (i + 1) mod 256;
  j = (j + S[i]) mod 256;
  Swap(S[i], S[j]);
  t = (S[i] + S[j]) mod 256;
  k = S[t];
}

3. Encrypt using X-OR

The plaintext is then XORed with k to generate the ciphertext. To generate plaintext from ciphertext, k is XORed with the ciphertext.

Example:
RC4 Encryption: 10011000 XOR 01010000 = 11001000
RC4 Decryption: 11001000 XOR 01010000 = 10011000
